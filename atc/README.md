# ATC Explorer

Compares 209 FAA towers and TRACONs as places to land, measured against
Warrenton, VA: pay after rent, rent, safety, distance, staffing need, outdoors
and training success, weighted by sliders you control.

Live at **https://tsuttonva.github.io/Skyframe2/atc/** once this is merged
to the deploy branch (it rides on SkyFrame's GitHub Pages site, the same way
HoofCast does at `/hoofcast/`).

It began as a single 246 KB HTML file (kept at `legacy/index-v23.html`). The
original brief is `HANDOFF.md`; this README describes what was built and where
it departs from that brief.

## What changed from the handoff

| Handoff said | What was built | Why |
|---|---|---|
| GitLab project, GitLab CI/Pages | A folder in this GitHub repo, GitHub Actions/Pages | SkyFrame2 is on GitHub. Living here reuses its Pages site, Cloudflare account and secrets, so there was nothing new to configure. |
| Supabase/Firebase or a Node service | A small Cloudflare Worker + KV (`worker/`) | Same stack SkyFrame already runs; deploys with the existing `CLOUDFLARE_API_TOKEN`. |
| Share link `/s/<token>` | `/atc/?s=<token>` | A static Pages site cannot route arbitrary paths. |
| Open question: who signs in, how? | Username + password, self-service signup | Decided by Tom. No email needed (the Resend account can only mail its owner). |
| Open question: do shares expire? | Never; owner can revoke | Decided by Tom. |
| Open question: proxy towers | Shown with a "borrowed: City" label | Decided by Tom. 27 towers. |
| Open question: automate 123ATC? | Yes, weekly | `robots.txt` allows `/facilities` and the site's terms (in its privacy page) say nothing against automated access. Checked 2026-11-16. |

## Run it locally

```
cd atc/site && python3 -m http.server 8788            # the app
cd atc/worker && npm install && npx wrangler dev      # the API on :8787 (local KV)
open "http://localhost:8788/?api=http://localhost:8787"
node --test atc/tests/*.test.mjs                      # from the repo root
```

The `?api=` override only works on localhost. Without the API the app still
works; you just cannot save or open share links.

## Saved scenarios and sharing

- A scenario stores **settings only**: weights, filters, sort, compared towers,
  map open/zoom. Scores are never stored. They are recomputed from the current
  data every time, so a refresh can change them.
- Scenarios are private to the account that saved them. The Worker checks a
  signed session token on every scenario request, and there is no endpoint that
  lists or reads another user's scenarios.
- **Share…** creates an unguessable 24-character token. `/atc/?s=<token>` shows
  that scenario read-only: its name, owner, settings and the full computed
  output. The viewer can move sliders to explore, but nothing saves back.
  A share shows the scenario as last saved, and records the data snapshot date
  from the day it was created so the viewer can see if the data has moved since.
- Shares never expire. **Share link… → Revoke link** kills one immediately;
  deleting the scenario does too. Sharing again makes a new token.
- Passwords are stored as salted PBKDF2-SHA256 hashes (100,000 iterations).
  There is **no password reset**. To reset someone by hand: Cloudflare dashboard
  → Workers KV → `atc-explorer-kv` → delete the key `user:<name>`. They can then
  sign up again under the same name and their scenarios (`scn:<name>`) are still
  there. Only do this for someone you can vouch for, since whoever re-registers
  the name gets those scenarios.
- Limits: 50 scenarios per account, 25 new accounts per day across everyone,
  150 saves per account per day. These exist to protect Cloudflare KV's free
  quota, which is shared with SkyFrame. See `docs/RATE_LIMITS.md`.

## Data refresh

Fast fields (level, CRWG target, current staffing %, min CPC pay, training
success) come from the table at https://123atc.com/facilities.
`.github/workflows/atc-refresh.yml` runs every Tuesday at 10:23 UTC, and can be
run by hand from the Actions tab.

Each run:

1. Reads the table **twice**, 5 seconds apart. The two reads must be identical.
2. Validates: row count within ±5% of the last snapshot; no required field
   (level, target, staffing, entry pay) newly blank; no more than 2% of tracked
   facilities missing; the table's columns unchanged.
3. Spot-checks 6 random facility pages (level and training success) against the
   table.
4. Only if all of that passes: writes `data/snapshots/123atc-<date>.csv`, merges
   into `data/current-123atc.json`, writes `data/changelog/<date>.md`, rebuilds
   `facilities.json`, runs the tests, commits, and triggers the Pages deploy.

If any check fails the job fails, **nothing is written**, and GitHub emails the
repo owner. The site keeps showing the last good data.

A value is never overwritten with a blank. If a field is blank at the source,
the last good value stays, and the app tags it "stale" with the date it was
last seen.

Being a polite guest: 8 requests per week in total, 5 seconds apart, with a
User-Agent that names this project and links here. If 123ATC ever objects or
blocks the job, stop the schedule and ingest a manual export instead:

```
node atc/scripts/refresh-123atc.mjs --file export.csv   # same columns as a snapshot CSV
node atc/scripts/build.mjs
```

Slow fields (Census, FBI, Zillow, OSM) are edited in `data/static.json` and
rebuilt with `build.mjs`. The handoff's pull scripts are in `pipeline/`.

Note: GitHub pauses scheduled workflows after 60 days with no repository
activity. A refresh that finds changes commits, which counts as activity, so
this should not come up in practice.

## Validation (the handoff's checks, as tests)

| Check | Where |
|---|---|
| Two independent reads of the table agree | `refresh-123atc.mjs` (runtime) |
| Spot-check facility pages against the table | `refresh-123atc.mjs --spot N` (runtime) |
| App level/target/staffing/entry pay/training match 123ATC for all facilities | `tests/data.test.mjs` |
| Row-count drift, blank-field and never-overwrite-with-blank rules | `tests/pipeline.test.mjs` |
| Scoring rules (weights, percentiles, 60% coverage, level/staffing filters) | `tests/core.test.mjs` |
| Private by default, share read-only, revoke works, no writes on reads | `tests/worker.test.mjs` |

The split app was also checked against the original: with the handoff's data,
every fit score, coverage, take-home and distance matched the single-file app
for all 209 facilities.

## Known gaps (shown honestly in the UI)

- **Crime, borrowed (27 towers):** the airport's own town has no usable FBI
  figure, so a nearby big city's rate is shown with a "borrowed: City" tag. It
  counts toward the fit score. ADW, IAD and PCT are not borrowed: they keep
  the hand-entered values from the original app, because the DC figure the
  handoff matched them to was flagged unreliable for suburban airports.
- **Crime, blank (8 towers):** GPT, JAN, NEW, ORL report zero offenses (looks
  wrong); ITO, OGG have no population figure; SJU, STT are outside the FBI file.
- **Savannah** keeps an earlier NeighborhoodScout value (355) because the FBI
  figure looks suspiciously low. Verify before trusting.
- **2BR rent** mixes Census gross rent (most towers) with RentCafe asking rents
  (the original 50, about 20% higher). Footnoted on the page.
- Price index, political lean and sports are blank for most of the 159 towers
  added later. SJU and STT are not on the map.
- Training success months differ by facility and small classes swing wildly.
- Take-home pay is an approximation, not tax advice.

## Deploying

Nothing to set up. On a push to the deploy branch:

- `pages.yml` publishes `atc/site/` at `/atc/`.
- `atc-worker-deploy.yml` deploys the Worker when `atc/worker/**` changes. It
  finds or creates the KV namespace `atc-explorer-kv` itself, using the same
  `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets as SkyFrame.

The front end expects the Worker at
`https://atc-explorer-worker.tom-tsutton.workers.dev` (`PROD_API` in
`site/src/cloud.js`), and the Worker only accepts browser calls from the
origins in `ALLOWED_ORIGINS` in `worker/wrangler.toml`.
